한정판 포토카드 채번: 쓰기량 1/100 최적화

Redis INCR + Kafka 이벤트 접기(Folding) + $max 멱등 벌크 업서트
⚠️ 과거 장애 배경

단일 도큐먼트의 $inc 연산에 의존하고 트랜잭션 범위를 비효율적으로 잡아 락 경합 및 대규모 포인트 환불/재지급 사태 발생.

🛡️ 4중 평탄화 메커니즘 효과
  • 인메모리 즉시 응답: Redis INCR로 사용자에게 초저지연 번호 즉시 반환
  • 접힌 쓰기 (Folded Write): Kafka 및 배치 워커에서 ID당 최대 1건으로 쓰기 압축
  • $max 멱등 보장: 네트워크 재시도 시에도 중복 없이 최종 정합성 완결
  • I/O 1/100 절감: 피크 타임에도 MongoDB 쓰기 부하를 극적으로 안정화
SESSION 3 · VECTOR & AI

고차원 벡터 메모리 및 레이턴시 병목 극복 파이프라인
✂️ Contextual Chunking

단순 오버랩 방식의 비효율 배제. 동일 문서 청크들을 배열로 묶어 컨텍스트 맥락을 온전히 보존한 채 임베딩 진행.

🪆 MRL 차원 절삭

전면부 차원에 핵심 정보가 집약된 Matryoshka 모델 채택. 재임베딩 비용 없이 1024차원을 256차원으로 즉시 Truncate.

📉 스칼라/바이너리 양자화

FP32 원본은 도큐먼트에 보관하고, Atlas Search 인덱스만 INT8/1비트로 압축하여 RAM 사용량 75~96% 절감.

SESSION 3 · DEEP DIVE

벡터 검색 파이프라인 5대 핵심 기술 비교

실무 적용 원리 및 시스템 리소스 절감 효과
단계 기술 요소 핵심 원리 및 실무 효과
01. Chunking Contextual Chunking
(Voyage AI)		 단순 오버랩 방식이나 매 청크마다 LLM을 재호출하는 비효율을 배제. 동일 문서의 청크들을 배열(Array)로 묶어 컨텍스트를 보존한 채 임베딩하여 문맥 유실 방지.
02. Similarity 유사도 메트릭 선정 Cosine: 텍스트 의미 각도 측정 (RAG 표준)  |  Dot Product: 벡터 크기(Norm)와 가중치 중요 시  |  Euclidean (L2): 이미지 공간 절대 거리
03. Dimension MRL 차원 절삭
(Matryoshka Learning)		 전면부 차원에 중요 정보가 집약되도록 사전 학습된 모델. 별도 재임베딩 비용 없이 상위 차원만 단순 절삭하여 1024차원 ➔ 256차원으로 즉시 경량화.
04. Quantize 스칼라 및 바이너리 양자화 FP32(32비트) 벡터 원본은 도큐먼트에 보관하고, Atlas Search 인덱스만 INT8(스칼라) 또는 1비트(바이너리)로 압축하여 RAM 사용량 75~96% 절감.
05. Reranker 2단계 파이프라인
(Cross-Encoder)		 1차로 경량 하이브리드 서치를 통해 Top-100 후보를 빠르게 필터링한 후, 2차 Cross-Encoder Re-ranker로 최종 정확도 정밀 보정.

에이전트 최적화 3대 핵심 전략

📝 컨텍스트 엔지니어링
  • RAG 검색 결과를 메인 LLM에 전달하기 전 SLM(경량 언어 모델)으로 사전 요약·압축.
  • 메인 모델의 입력 토큰 소모량을 40~60% 절감하여 추론 비용 및 레이턴시 단축.
  • 질의와 무관한 잡음(Noise) 필터링 효과.
⏳ 선택적 망각 (TTL Index)
  • 수명이 다한 워킹/에피소딕 메모리는 TTL(Time-To-Live) 인덱스로 자동 소멸.
  • 오래된 불필요한 대화 컨텍스트 누적으로 인한 컨텍스트 오염 및 환각(Hallucination) 원천 차단.
  • 스토리지 낭비 없는 청정 메모리 유지.
🛠️ 도구 내재화
  • 외부 MCP 도구(Tavily 등) 호출 패턴 및 결과를 프로파일링.
  • 자주 발생하는 고빈도 질의 패턴을 MongoDB 내부 빌트인 커맨드/인덱스로 자동 승격.
  • 외부 API 네트워크 비용 및 RTT 제로화.

SESSION 5 · DATA MODELING

워크로드 중심의 MongoDB 데이터 모델링 방법론

👤 방선구, 강승욱 (MongoDB 수석 솔루션 아키텍트)
🔍 1~2단계: 비즈니스 & 워크로드 파악
  • 데이터 자체의 형태보다 "어떤 쿼리가 어떤 빈도로 호출되는가"를 최우선 분석.
  • 읽기 집약적(Read-Heavy) vs 쓰기 집약적(Write-Heavy) 워크로드 구분.
  • 가장 중요한 임계 경로(Critical Path) 쿼리의 I/O를 1회로 수렴시키는 것이 목표.
🎯 3~4단계: 관계 매핑 & 패턴 최적화
  • 카디널리티 크기(1:소수 vs 1:무한)에 따라 임베딩과 참조를 명확히 분기.
  • 확장 참조 패턴으로 메인 뷰 조회 I/O 1회 단축.
  • 계산 패턴으로 반복 집계 부하 제거 & $jsonSchema로 데이터 거버넌스 확보.
SESSION 5 · DECISION TREE

엔티티 관계: 임베딩(Embedding) vs 참조(Referencing)

실무 의사결정 체크리스트 및 패턴 선택 흐름
📌 확장 참조 패턴 (Extended Reference)

전체 주문은 참조 컬렉션으로 분리하되, 마이페이지 첫 화면 조회에 필요한 "최신 3건 주문 요약(orderId, date, total)"만 고객 문서에 복제 내장하여 메인 화면 조회 I/O를 1회로 단축.

⚡ 계산 패턴 (Computed Pattern)

조회 시점마다 리뷰 목록을 AVG(), COUNT()로 집계하지 않고, 리뷰 작성 시점에 numberReviews, averageRating을 사전 계산하여 제품 문서에 기록.

🛡️ 스키마 검증 ($jsonSchema)

유연한 도큐먼트 모델을 유지하면서도 프로덕션 필수 필드 누락을 방지하기 위해 DB 엔진 레벨에서 JSON Schema 밸리데이션 강제 적용.

01. 현대 모델링 패러다임

디스크 용량을 아끼던 과거 정규화 시대에서, 네트워크 및 디스크 I/O를 1회로 줄이는 도큐먼트 내장 및 역정규화 시대로 완전히 전환되었습니다. "함께 조회되는 데이터는 함께 저장한다"는 원칙이 핵심입니다.

02. 극한 트래픽 운영 효율

전담 DBA가 없더라도 In-Memory 캐시(Redis) ➔ 비동기 버퍼(Kafka) ➔ MongoDB Atlas의 3계층 방어선과 접힌 쓰기(Folded Write)를 통해 70K RPS 이상의 극한 트래픽을 완벽히 흡수할 수 있습니다.

03. AI-Ready 단일 인프라

분산된 벡터 DB, 전문 검색 엔진, 캐시를 파편화하여 운영할 필요 없이, MongoDB Atlas 단일 플랫폼 내에서 Operational Data, CoALA 5계층 메모리, 벡터 검색, 시계열 압축을 통합 구현하는 것이 엔터프라이즈 AI 성공의 지름길입니다.

GLOSSARY · PART 1

기술 용어 해설: 데이터베이스 모델링 및 아키텍처

📦 정규화 vs 역정규화 & I/O-Bound
  • 정규화 (Normalization): 무결성과 저장공간 절약 목적의 설계. 다중 조인으로 인한 I/O 병목 발생.
  • 역정규화 (Denormalization / Embedding): 연관 데이터를 단일 도큐먼트 내에 내장하여 1회의 I/O로 완결.
  • I/O-Bound: CPU 연산 속도가 아닌 디스크 읽기/쓰기 및 네트워크 전송 지연이 전체 시스템의 한계가 되는 상태.
📐 고급 디자인 패턴
  • 확장 참조 패턴 (Extended Reference): 전체 데이터는 참조 분리하되, 최신 3건 등 빈번한 핵심 필드만 부모 문서에 복제 내장.
  • 계산 패턴 (Computed Pattern): 읽기 시점의 반복 집계(SUM, AVG)를 없애기 위해 쓰기 시점에 사전 연산하여 필드에 기록.
  • Unbounded Array 방지: 배열 크기 무한 증가로 인한 16MB 초과 위험 및 메모리 단편화 방지 설계.
🔄 CDC (Change Data Capture)

소스 DB 트랜잭션 로그(MySQL Binlog, Mongo Oplog)를 실시간 감지하여 타깃 DB로 지연 없이 스트리밍 복제하는 무중단 마이그레이션 기반 기술.

📈 Time Series Collection

시계열 데이터를 메타데이터와 타임스탬프 기준으로 내부 자동 버킷팅(granularity)하여 일반 도큐먼트 대비 18배 이상의 압축률과 빠른 범위 질의를 제공하는 전용 엔진.

GLOSSARY · PART 2

기술 용어 해설: 대규모 트래픽 분산 엔지니어링

🛡️ 3계층 트래픽 방어선
  • 1층 (READ 방어선): Redis Cluster (캐시 조회, 분산락, 원자적 카운터)
  • 2층 (WRITE 평탄화선): Kafka / SQS 비동기 버퍼링 & 2초/50건 배치
  • 3층 (Source of Truth): $max 멱등 적재를 수행하는 MongoDB Atlas
⚡ 접힌 쓰기 (Folded Write)

동일한 키(ID)에 대해 단시간에 발생하는 수만~수십만 건의 갱신 이벤트(하트 클릭, 조회수 등)를 배치 워커 메모리 상에서 최종 상태 1건으로 접어(Merge) 단일 쿼리로 실행함으로써 DB 쓰기 I/O를 1/100로 절감.

🔒 멱등성 및 $max 벌크 업서트

네트워크 재시도나 메시지 중복 전달이 발생해도 데이터가 덮어씌워지거나 뒤틀리지 않도록, 기존 값보다 큰 최신 상태값만 반영되도록 보장하는 원자적 갱신 기법.

🔄 Primary Stepdown & DLQ
  • Primary Stepdown: 무중단 롤링 패치 시 기존 Primary가 Secondary로 권한을 넘기는 과정. 지수 백오프 및 보상 트랜잭션으로 극복.
  • DLT / DLQ: 처리 실패한 메시지를 격리 보관하여 데이터 유실을 방지하는 전용 대기열.
GLOSSARY · PART 3

기술 용어 해설: AI, 벡터 검색 및 지식 검색 (RAG)

✂️ Contextual Chunking

상위 문서의 전체 맥락(제목, 주제, 상위 요약)을 각 청크 메타데이터로 함께 주입하여 임베딩함으로써 청크 분할 시 발생하는 문맥 유실과 검색 단절을 원천 방지.

🪆 MRL (마트료시카 학습)

벡터 앞쪽 차원에 핵심 의미를 집약하도록 사전 학습된 모델. 별도 재임베딩 비용 없이 1024차원 상위 256차원만 잘라내어(Truncate) 인덱스 메모리를 대폭 절약.

📉 벡터 양자화 (Quantization)

FP32 부동소수점 벡터를 INT8(스칼라) 또는 1비트(바이너리) 정수로 압축 변환하여 Atlas Vector Search 인덱스 RAM 사용량을 75~96% 절감.

📐 유사도 메트릭
  • Cosine: 사잇각 측정 (텍스트 의미 RAG 표준)
  • Dot Product: 벡터 크기와 가중치 반영
  • Euclidean: 기하학적 절대 거리 측정
🎯 Re-ranker (Cross-Encoder)

1단계에서 하이브리드 검색으로 빠르게 Top-100 후보를 추출한 후, 2단계 Cross-Encoder로 문맥 상호작용을 정밀 계산하여 최종 순위를 보정하는 기법.

🌐 온톨로지 Graph RAG

개념 스키마(T-Box)와 사실 데이터(A-Box)를 결합한 지식 그래프를 통해 다단계 조인을 1회 탐색으로 해결하고 쿼리 환각을 방어하는 고도화 RAG.

GLOSSARY · PART 4

기술 용어 해설: 자율형 AI 에이전트 및 거버넌스

🧠 CoALA 인지 아키텍처 5계층 메모리
  • Working Memory: 현재 대화 세션의 즉각적 컨텍스트 (TTL 2h)
  • Episodic Memory: 과거 작업 이력 및 성공/실패 경험 (TTL Long)
  • Semantic Memory: 기업 사실 지식, 세계관, 도메인 캐시 (TTL Long)
  • Procedural Memory: 행동 규칙, 프롬프트 가이드라인, 기업 정책
  • Shared Memory: 멀티 에이전트 간 작업 인계(Handoff)용 공유 메모리
⏳ TTL Index (선택적 망각)

만료 기한이 지난 도큐먼트를 백그라운드 스레드가 자동 소멸시키는 인덱스. 에이전트 시스템에서 오래된 불필요 단기 기억을 자동 소멸시켜 컨텍스트 오염 및 환각(Hallucination)을 원천 차단.

🔌 MCP (Model Context Protocol)

LLM 애플리케이션이 외부 도구, 데이터베이스, API와 안전하고 표준화된 규격(JSON-RPC 기반)으로 상호작용하도록 정의된 오픈 표준 프로토콜.

👤 Human-In-The-Loop (HITL)

AI가 문제를 진단하고 해결책을 자율 제안하더라도, 인덱스 생성이나 결제 승인 등 영향도가 큰 위험 작업은 반드시 인간 운영자의 최종 보안 승인을 거치도록 하는 통제 거버넌스.
